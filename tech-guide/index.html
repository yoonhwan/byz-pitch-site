TG-01

개요 & 퀵스타트

BYZ-Agents는 Gateway · Redis · Worker 3계층으로 구성된 분산 실시간 AI 통역 시스템입니다. 마이크 입력부터 다국어 음성 출력까지 LangGraph 상태 머신 파이프라인으로 처리합니다.

시스템 개요

BYZ-Agents는 국제 회의·온라인 미팅 등 다국어 환경에서 실시간 통역을 제공하는 백엔드 시스템입니다. 브라우저 마이크(PTT)로 발화된 음성이 WebSocket을 통해 Gateway에 도달하고, Redis Stream → Worker(LangGraph)를 거쳐 STT → 번역 → TTS 결과가 SSE로 클라이언트에 스트리밍됩니다.

TG-02

아키텍처

BYZ-Agents의 3-Tier 분산 구조, 모듈 의존성 규칙, Redis 이벤트 토폴로지를 설명합니다. CLM-004 VERIFIED

3-Tier 구조

시스템은 Gateway(API 진입점) — Redis(메시지 브로커) — Worker(처리 엔진) 세 계층으로 분리됩니다. Gateway와 Worker는 서로 직접 통신하지 않으며, 오직 Redis Stream과 Pub/Sub을 통해서만 메시지를 교환합니다.

Gateway 계층

FastAPI 기반 ASGI 서버로, 클라이언트의 모든 HTTP/WebSocket/SSE 연결을 처리합니다. JWT 인증, 크레딧 검증 후 STT 요청을 Redis Stream에 발행합니다.

기능구현
실시간 음성 수신WebSocket /ws/v1/stt/realtime
결과 스트리밍SSE (Server-Sent Events)
인증JWT Bearer Token
Redis 발행XADD → STT 요청 Stream

Worker 계층

LangGraph 기반 상태 머신(build_pulse_graph)으로 STT → 번역 → TTS 파이프라인을 실행합니다. PulseStreamConsumer가 Redis Stream을 소비하고 처리 결과를 Redis Pub/Sub으로 브로드캐스트합니다. CLM-005 VERIFIED 

# Worker 핵심 모듈 구조
worker/
  infrastructure/
    consumers/
      pulse_consumer.py     # PulseStreamConsumer — Redis XREAD 소비
  graph/
    pulse_graph.py          # build_pulse_graph — LangGraph 상태 머신

의존성 규칙

Gateway ↔ Worker 직접 의존 금지

⚠️ 중요 — Gateway와 Worker는 Python import 레벨에서 서로를 참조해서는 안 됩니다. 모든 통신은 Redis Stream/Pub/Sub 이벤트로만 이루어집니다. 
# 허용되는 의존 방향
gateway ──────────────► shared   (공통 모델, 유틸리티)
worker  ──────────────► shared
cli     ──────────────► shared.config (설정 값만)

# 금지
gateway ─── ✕ ───────► worker   (직접 import 금지)
worker  ─── ✕ ───────► gateway

Redis 역할

Redis Stream (STT 요청 큐)

Gateway가 XADD로 STT 요청을 발행하고 Worker가 XREAD로 소비합니다. Consumer Group으로 다중 Worker 확장이 가능합니다.

# Gateway → Worker: STT 요청 발행
XADD byz:stt:requests * session_id {sid} audio_chunk {base64}

# Worker: 소비
XREAD GROUP pulse-workers consumer-1 COUNT 10 STREAMS byz:stt:requests 0

Redis Pub/Sub (결과 브로드캐스트)

Worker가 처리 결과(stt.partial, translate.done, tts.ready)를 Pub/Sub 채널로 발행하고 Gateway SSE가 구독합니다.

# Worker → Gateway: 번역 결과 발행
PUBLISH byz:session:{session_id}:events '{"type":"translate.done","lang":"en","text":"..."}'

# Gateway SSE: 구독 후 클라이언트에 스트리밍
SUBSCRIBE byz:session:{session_id}:events

LangGraph 상태 머신

build_pulse_graph()는 LangGraph StateGraph로 파이프라인을 정의합니다. 각 노드는 비동기(async) 함수로 구현되며, 노드 간 상태 전달은 TypedDict로 관리됩니다. 

# 간략 구조 (개념 코드)
from langgraph.graph import StateGraph

graph = StateGraph(PulseState)
graph.add_node("stt",       stt_node)
graph.add_node("assemble",  assemble_node)
graph.add_node("translate", translate_fan_out_node)   # Fan-out
graph.add_node("polish",    polish_node)
graph.add_node("tts",       tts_node)

graph.set_entry_point("stt")
graph.add_edge("stt",      "assemble")
graph.add_edge("assemble", "translate")
graph.add_edge("translate","polish")
graph.add_edge("polish",   "tts")

pulse_graph = graph.compile()

번역 Fan-out

다국어 동시 번역

Translate Node(Node 3)는 방 참여자의 언어 목록을 기반으로 여러 번역 작업을 병렬(asyncio.gather)로 실행합니다. Redis Pub/Sub으로 각 언어별 결과를 브로드캐스트합니다.

ℹ️ 지원 언어 목록(CLM-003)은 아직 [UNVERIFIED] 상태입니다. STT/TTS 프로바이더 설정에 따라 지원 언어가 달라집니다. tech-guide 내부 참고용으로만 사용하세요.

TTS 처리 흐름

TG-05

클라이언트 연동

Next.js 클라이언트에서 실시간 통역을 구현하는 React Hook 및 SSE 이벤트 스펙입니다.

싱글 통역 (Solo)

useRealtimeSolo Hook

1:1 통역 세션을 관리하는 커스텀 훅입니다. PTT 상태, SSE 연결, 오디오 청크 전송을 담당합니다. 

// 사용 예시 (개념 코드)
const {
  isPttActive,    // PTT 버튼 활성 상태
  startPtt,       // PTT 시작 (마이크 오픈)
  stopPtt,        // PTT 종료
  transcript,     // stt.partial/final 텍스트
  translation,    // translate.done 텍스트 (언어별)
  ttsAudio,       // tts.chunk 오디오 재생 큐
  connectionState // 'connecting' | 'connected' | 'error'
} = useRealtimeSolo({ targetLang: 'en' });

PTT 흐름

  1. 사용자가 PTT 버튼을 누름 → startPtt() 호출 → WebSocket 연결 + MediaRecorder 시작
  2. 100ms 단위 오디오 청크가 WebSocket으로 Gateway에 전송
  3. Gateway가 Redis Stream에 발행 → Worker STT 처리 → SSE로 partial 결과 수신
  4. PTT 버튼 해제 → stopPtt() → MediaRecorder 중단 → final STT 이벤트 수신
  5. Translate Fan-out → Polish → TTS → 오디오 재생

멀티 통역방 (Room)

useRealtimeRoom Hook

다중 참여자 방 세션을 관리합니다. 방 생성/참여, Speaker Lock 상태, 참여자 목록을 포함합니다. 

// 개념 코드
const {
  roomId,         // 현재 방 ID
  participants,   // 참여자 목록 [{userId, lang, status}]
  speakerLock,    // 현재 발화자 userId (null이면 발화 가능)
  myLang,         // 내 언어 설정
  createRoom,     // 방 생성 → roomId 반환
  joinRoom,       // roomId로 방 참여
  startPtt,       // Speaker Lock 획득 + 발화 시작
  stopPtt,        // Lock 해제
  translations,   // { [userId]: { text, lang } }
} = useRealtimeRoom();

Speaker Lock 규칙

상태설명
Lock 없음누구든 PTT 가능
Lock 획득PTT 누름 → Redis SETNX로 Lock 획득 → 독점 발화
Lock 경쟁다른 참여자 PTT 시도 → Lock 실패 → 대기
Lock 해제PTT 해제 → Redis DEL → 다음 발화자 가능
